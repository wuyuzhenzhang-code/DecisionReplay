# AI 使用与验证记录

## 参与方式

- 开发工具：Codex。参与产品范围收敛、界面、类型定义、算法、服务端模型调用、测试、部署尝试和文档。
- 产品内模型：OpenAI Responses API，默认 `gpt-5-mini`，可通过服务端 `OPENAI_MODEL` 调整。实际连通返回的模型版本为 `gpt-5-mini-2025-08-07`。
- 模型职责：提取假设、组织证据、提出缺失证据问题、提示有证据支持的偏差线索、生成学习检查项。
- 确定性代码职责：输入校验、事前筛选、金额计算、引用与输出结构校验、模式标识、存储与导出。
- 未使用多 Agent 编排、向量库、自动交易或隐藏的市场数据替代。

## 真实发现与修正

1. 仅用极小输出上限测试连通时 API 返回 `incomplete`。此结果只证明能调用，未作为完整 AI 功能验收。
2. 初次完整事前报告引用合法，但出现“价格上行被视为市场反应”“存在关注短期价格的倾向”等超出理由原文的推断。人工抽查由 Codex 执行，增加“不得从走势推断用户心理或注意力”的明确指令。结构校验不能保证每条推断真实，仍将语义抽查列为边界。
3. 初次事后报告的清单来源引用未通过校验，服务端返回 `invalid_report` 并阻止整份报告。随后增加最多一次基于校验错误的重新生成；第二次仍无效则继续返回失败。没有静默去掉引用保留断言。
4. 修正窗口热更新中断导致的开发预览错误，恢复服务后重新实际操作。该失败没有被记录为通过。
5. 修复 TypeScript 对未知 HTTP JSON 的类型错误，并为测试函数补齐类型。最终以实际类型检查结果为准。

## 约束与透明度

模型请求使用服务端重建的允许证据；不传案例标题、备注、未来交易或排除的理由。模型输出数字必须引用确定性指标键，文本内阿拉伯数字会导致校验拒绝。报告按 fact / inference / uncertain 标识。交易建议类问题在模型调用前拦截，并受系统指令与输出检查约束。任意语言改写的恶意请求不保证百分之百拦截。

提示词、CSV、理由和事件原文均视为不可信数据。模型没有任何交易工具、文件读取工具或密钥读取工具。模型输入本身不包含 API Key。

事前筛选和证据校验不能抹除模型训练中的历史知识，也不证明引用与结论在语义上完全对应。来源真实性、发布时间声明和因果判断仍需人工核验。
